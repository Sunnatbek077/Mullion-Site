Entry level

You do not need the expensive Mac.

An M1 MacBook Air from 2020, or a MacBook Neo — the cheapest laptop Apple has ever sold — will hold a Cyberpunk-class game at 30–40 fps, and hold it smoothly. One hop to Metal instead of two is what buys you the difference.

Help it breathe MacBook Neo · No Man's Sky
As it ships 30 fps 105 °C
Cooled properly 58 fps 83 °C

A fanless Mac runs out of thermal headroom long before it runs out of chip — nothing changed here but the path the heat takes out. A stand, a cooling pad, or a real thermal mod is the cheapest frame rate you will ever buy.

Tested by ETA Prime — a stock MacBook Neo against the same machine with a copper heat spreader fitted. Written up by Notebookcheck and Hackaday.

Graphics

DirectX to Metal.
One hop.

Most Wine setups translate DirectX into Vulkan, then lean on MoltenVK to turn Vulkan into Metal. Mullion runs an engine whose D3D libraries are D3DMetal — no second translation, no Vulkan in the path at all.

Full environment

Running this engine with a smaller environment than CrossOver measurably slows games down. Mullion sets all of it.

MetalFX on

Without D3DM_ENABLE_METALFX the adapter reports as AMD, and DLSS-capable games silently disable their upscaler.

Tuning is free

Engine settings are never behind a paywall. Charging for them would mean shipping free users a slower game.

Your library

Steam. Epic. GOG.
Already there.

Connect an account and Mullion lists what you own, downloads it, and wraps it — using the same tools these platforms' own community launchers use, installed and pinned for you.

Resumable

Pause a download and the finished chunks stay. Relaunch after a reboot and the queue is still there.

Honest progress

Credentials stay put

Passwords go to the store's own tool over stdin — never as arguments, and never to a Mullion server. There isn't one.

Control

Nothing to set up.
Everything still there.

Most tools in this category pick a side. One hands you every Wine setting and expects you to know which one you need; the others hide all of it and hope you never ask. Mullion is not a compromise between those — it is both, layered.

The default path

You configure nothing

  • Drop a folderMullion walks it, skips installers and crash handlers, reads the PE header for x86 or x64, and picks the executable itself.
  • A recognised game arrives configuredDirectX version, Windows version and the packages it needs are already filled in — and an unrecognised one says so plainly instead of showing a tick it has not earned.
  • The prefix and engine are handledA prefix is cloned from the shared base, the full engine environment is set, the launcher and icon are written. You press Build.

Neither half is a mode you switch into. The depth lives on its own screen, so it is never in the way of a build — and the defaults are complete, so reaching for it is a choice rather than a requirement.

Read, not assumed

Set a prefix's Windows version and Mullion parses the registry back out to show what it actually says — not what was requested.

Per app, not per prefix

Two wrapped games can share one prefix and still differ: a launcher's own variables are written after the prefix block, so the later value wins.

Safe to undo

Deleting a prefix waits for a running install to finish rather than pulling the folder out from under it.

Deliberately absent

No AI.
Not one feature.

No assistant, no chat box, no “smart” suggestions, no model running on your Mac or in somebody's cloud. Nothing you do here is sent to one. The app makes exactly one outbound request that is not a download — a HEAD to read a component's size.

This is not a gap waiting for a future update. Wrapping a game is a mechanical problem with a right answer: read the executable's header, clone the prefix, set the environment, write the launcher. None of it improves by guessing — and an app that guesses about your files is an app you have to check. You are not funding anyone's inference bill either.

Where the money goes

Into staying
compatible.

This is a translation layer between two operating systems that are both still moving. Every macOS release can break Wine, break D3DMetal, or change what a graphics driver reports. When there is revenue, all of it goes to keeping this working on macOS 28 and whatever comes after.

Every published Wine and GPTK build is Intel-only, so all of this runs on Rosetta 2. If Apple retires it, the engine has to be replaced rather than patched — the app is built so that swap is one component and no interface changes, but somebody still has to do the work.

Built on other people's work

Wine — thirty years of reimplementing the Windows API, by hundreds of contributors. LGPL-2.1-or-later.
CodeWeavers — CrossOver — the largest contributor to Wine, and the authors of the macOS work that made this practical. The engine Mullion runs is theirs.
Apple — Game Porting Toolkit, D3DMetal — the DirectX-to-Metal translation, itself built on Wine and CodeWeavers' work. One lineage, not three.

Shipped inside Mullion

winetricks — Dan Kegel, Austin English and contributors. LGPL-2.1-or-later.
cabextract — Stuart Caie. GPL.

Fetched when you connect a store

DepotDownloader (SteamRE), Legendary and gogdl (Heroic Games Launcher).

Privacy

Mullion uploads nothing — not your library, not your game names, not a usage ping. The app makes exactly one outbound request that is not a download: a HEAD to read a component's size.

The store tools it runs are a different matter: Steam, Epic and GOG each receive your credentials, because signing in to a store means signing in to that store. Everything Mullion writes stays in ~/Mullion.
